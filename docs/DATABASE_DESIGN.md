# Database Design

**Status:** Phase 2 identity + planning schema implemented (13 tables); live migrations pending
**Database:** PostgreSQL 16+  
**ORM:** Prisma

## Principles

- Every user-owned record is scoped to a personal `Workspace`.
- IDs are UUIDs generated by the application/database, not enumerable integers.
- Secrets are never stored in workflow definitions, messages, audit payloads, or logs.
- Plans and workflow versions are immutable JSON snapshots with hashes and monotonically increasing per-parent versions.
- Execution rows reference the exact workflow version and are append-only except for controlled status/lease transitions.
- `deletedAt` is reserved for recoverable user-facing entities; credentials and sessions use revocation/expiry. Hard deletion and retention jobs are separate operations.

## Phase 1 tables

### `users`
- `id` UUID primary key; `workspaceId` unique FK to `workspaces`.
- Unique normalized `email`; `passwordHash` is nullable only for future OAuth-only accounts.
- `displayName`, `preferredLanguage` (`en`/`ar`), IANA `timezone`, optional `usageCategory`, `dateFormat`.
- `emailVerifiedAt`, `onboardingCompletedAt`, `status`, timestamps.
- Password hashes and tokens are never serialized by API response mappers.

### `workspaces`
- `id`, unique `slug`, `name`, `planCode` (default `free`), timestamps.
- MVP has exactly one owning user; no team membership table is introduced prematurely.

### `sessions`
- `id`, `userId`, `workspaceId`, unique SHA-256 `tokenHash`.
- `expiresAt`, `lastSeenAt`, optional `revokedAt`, IP/user-agent metadata with documented retention.
- Indexes support token lookup and user/session revocation.

### `auth_tokens`
- Single-use hashed tokens for email verification and password reset: `id`, `userId`, `purpose`, `tokenHash`, `expiresAt`, `consumedAt`, `createdAt`.
- Raw tokens exist only in the delivery message.

### `audit_logs`
- `id`, nullable `workspaceId`/`actorUserId` for pre-auth events, `action`, `targetType`, `targetId`, safe JSON `metadata`, request ID, IP hash, timestamp.
- Audit payloads are allowlisted and never contain request bodies or secrets.

## Phase 2 tables

### `conversations`
`id`, `workspaceId`, `userId`, `title`, `status`, safe `draftState` JSON, `createdAt`, `updatedAt`, `archivedAt`. Queries always include workspace ownership; the user/workspace relation is composite.

### `messages`
`id`, `conversationId`, `workspaceId`, `role`, `kind`, redacted `content`, safe structured `payload`, optional `clientMessageId`/`planId`, `createdAt`. Safe error codes live in payload metadata. A uniqueness key on client message ID plus conversation prevents duplicate user submissions.

### `automation_plans`
`id`, `conversationId`, `workspaceId`, `version`, `status`, immutable `definition` JSONB, `contentHash`, `feasibility`, `createdAt`. Unique `(conversationId, version)`.

### `plan_approvals`
`id`, `planId`, `workspaceId`, `approvedByUserId`, `planHash`, `approvedAt`. The hash must match the referenced immutable plan in a transaction.

## Phase 3+ tables

### `workflows` and `workflow_versions`
Workflow head records hold workspace ownership, name, lifecycle state, current published version, active version, schedule metadata, and timestamps. Versions hold immutable canonical `definition` JSONB, `version`, `contentHash`, source plan/approval, validation status, and change summary. Updating an active workflow creates and validates another version; no in-place JSON mutation is allowed.

### `connections` and `workflow_connections`
Connections hold workspace ownership, provider/type, display name, status, scopes, nonsecret external account metadata, encrypted envelope columns, key version, expiry, revocation, and timestamps. Workflow join rows reference connection IDs, never copies of credentials.

### `executions` and `execution_steps`
Executions hold workspace/workflow/version IDs, trigger, idempotency key, queued/running/final status, timing, lease, attempt, sanitized error, and dry-run/live mode. Steps hold node ID/version, attempt, status, duration, redacted output sample, categorized error, and provider uncertainty marker. Unique dispatch keys prevent accidental duplicates.

### `usage_records`, `notifications`, and `idempotency_keys`
Usage is server-generated and aggregated by workspace/period. Notifications have kind, safe payload, read timestamp, and delivery state. Stored mutation idempotency responses expire and are scoped by workspace, route, and key.

### Later/beta
`webhook_endpoints`, `webhook_events`, `subscriptions`, `billing_events`, and `system_settings` remain unimplemented until their phase. Billing tables are not needed for the MVP identity/runtime path.

## Integrity and indexing

- Foreign keys are indexed; ownership columns have composite indexes matching lookup patterns.
- Version uniqueness is enforced by database constraints, not only application checks.
- Unique normalized emails and session/token hashes are database constraints.
- Execution history is indexed by `(workspaceId, workflowId, createdAt DESC)` and retained by policy.
- JSONB is used for immutable definitions and safe metadata, not for authoritative ownership fields.
- Destructive cascades are limited to hard account/workspace deletion; ordinary workflow archival must preserve audit/history.

## Migration and recovery policy

Migrations are checked into `packages/database/prisma/migrations`. Deployment runs migrations once before API/worker rollout. Backup and restore commands belong in the operations guide; restore drills must verify queue deduplication so recovered schedules do not duplicate external effects.
